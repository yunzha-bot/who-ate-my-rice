# S5｜住宅平面图版 3D 灰盒地图（Gate = PASS）

本方案以用户提供的 `D:\桌面\偷大米小游戏\场景图.png` **左侧平面图**为位置基准，按追逐与镜头可读性放宽房间、门洞、走廊和家具间距。旧版等大房间 3×3 九宫格方案为 **Deprecated / 已废弃**。数据在 `src/three/map/apartmentMap.ts`；Three.js 几何与碰撞由 `src/three/map/MapBuilder.ts` 建立。X/Z 是地面，Y 是高度；下文坐标是游戏尺度，不是实际房屋测绘尺寸。

## 房间连接与自然追逐环路

门洞/半开放连接由 `DOOR_NODES` 描述，每个节点有 ID、坐标、旋转、宽度和两侧 Room ID。当前始终开放，顶部橙色横梁只是调试占位，**没有门玩法**。共享墙面只有指定连接处开口，不是每面墙都开门。门前后用角色尺度检查，不把家具直接塞到门洞口。

人工跑图的三条主环路：

1. **公共区**：客厅 → 餐厅 → 厨房 → 客厅。餐厅桌可在环内绕行。
2. **主卧区**：主走廊 → 主卧 → 衣帽间 → 主走廊。主卧床可从两侧绕开。
3. **卧室区**：主走廊 → 卫生间 → 次卧 → 书房 → 主走廊。书房另有通往玄关的次入口。

此外阳台连接客厅与厨房，储物间连接厨房与餐厅，玄关连接书房、客厅和餐厅；关闭连接图中任一单个 DoorNode 后其余区域仍可达。上述“可达”已由自动空间检查与 S5 人工跑图验收共同确认。

## 家具、节点与出生

- 家具障碍：客厅沙发、茶几、电视柜；餐桌；厨房操作台、岛台、冰箱；储物柜；主卧床、衣柜；衣帽间衣柜；卫浴；次卧床、柜；书桌、书柜；玄关长凳。均为灰盒 BoxGeometry，并使用相同几何体作为碰撞范围。主要家具之间保留多方向绕行空间。S7C-1A 另加 **2 个藏身用白模纸箱**：客厅 `living_carton (7.9, 3.9)`、储物间 `storage_carton (15.7, -4.8)`，均为 0.9×0.9×0.75，同样只写一行 `FURNITURE` 数据并复用 `addObstacle` 的 BoxGeometry 与静态碰撞（无正式美术）。
- 家具净距示例（按碰撞矩形边缘估算）：客厅沙发与茶几约 `1.3`，厨房岛台与操作台约 `1.8`，餐桌到餐厅左右墙各约 `2.1`，主卧床到左/右墙约 `2.95 / 3.95` 世界单位。角色直径约 `0.533`；这些数值用于灰盒摆放检查，最终绕行手感仍由人工跑图确认。
- `RiceCandidate` 共 14 个：阳台 1、客厅 2、餐厅 2、厨房 2、储物间 1、主卧 1、衣帽间 1、卫生间 1、次卧 1、书房 1、主走廊 1。散布在家具旁、角落与转角，而非机械平均放在房间中心。
- 每局从 14 点无重复随机激活 5 份；R 重开重抽。每份开发进食时间 5 秒、正式设计 60 秒，0.4 秒准备不计入正式进度；5 份米的累计正式进食 ÷ 5 份总量用于冲刺 30% 风险判定。
- DeepSeek 出生：玄关 `(6.2, 9.7)`；Human 出生：厨房 `(10.3, -4.4)`。二者位于不同空间，非旧九宫格对角出生。
- HideSpot：S5 曾有 5 个占位点；**S7C-1A 已扩展为 8 个带锚点的藏身点配置**（见文末「S7C-1A」一节）。仍然**只有地图数据与调试标记，不实现进入 / 退出 / 检查**。
- `DEBUG_MAP = true` 时显示房名、14 个候选点 ID、当前激活的亮米色米块、DoorNode 简码、出生点、家具碰撞轮廓，以及藏身点调试标记（中文名 + 藏身点 ID + 类型 + 锚点坐标两行精灵，并在地面画出锚点小方块）。藏身点标记只在 `DEBUG_MAP` 开启时生成，普通玩家视图不包含任何藏身点信息。
- 阵营选择页临时采用全图俯览以便对照平面图；选定阵营后恢复 S4.5 的原有相机视域与角色中心跟随。

## S5 边界与人工 Gate

保留 OrthographicCamera、相机相对移动、镜头跟随、双阵营、IJKL 调试控制、持久进食、阶段式冲刺、抓捕、Esc 暂停、R 重开与 M 返回阵营选择。本轮只更换地图位置、墙体、家具和逻辑节点；不做 AI、正式美术、锁门、PulseLock、声音或完整 S6A 大米表现。

锚点规则（全部由测试强制）：可站立（`canOccupyStaticXZ`，圆半径 0.23 / 身高 0.7）；距所属家具 AABB ≥ 0.05；距最近门段 ≥ 2.0（不与 `E` 开门 / 锁门抢键）；距最近米点 ≥ 1.2（不落在 1.0 的进食范围内）；距可用导航格心 ≤ 0.45；从两个阵营出生点 A* 均可达；锚点不落在任何墙 / 家具盒内（藏身点自身**不新增碰撞体，也不新增导航障碍**）。

- **纸箱**：`living_carton (7.9, 3.9)` 与 `storage_carton (15.7, -4.8)`，均 0.9×0.9×0.75，只是两行 `FURNITURE` 数据。`storage_carton` 在 S7C-0 设计中建议的 z 是 -2.6，实测会与米点 `rice_08 (16.1, -3.3)` 只隔 0.250、把该米点标记压住（既有 `tests/apartment-map.test.mjs` 判定 `rice blocked rice_08`），因此沿储物间西墙北移到 z = -4.8（距 `rice_08` 中心 1.55）。两个纸箱都不压门、不压门前后 1 个角色直径处、不压任何米点，也没有把任何「加箱前仍可站立」的格切成分离区域。
- **床底**：`main_bed` / `second_bed` 本阶段**只登记床边锚点**，**没有改床的实心碰撞**，角色不会穿进床体；真正的「钻床底」（床框 + 空洞碰撞）须另提专项设计单独批准。
- **遗留观察与用户决定**：`hide_main_wardrobe` 与 `hide_closet` 的锚点在角色圆之外只剩 0.030 / 0.025 世界单位余量（其余 6 个为 0.070–0.220），因为采用已批准的 3.1 原值；`living_carton` 距客厅东墙与南墙各 0.56，其东 / 南两侧各剩一条约 0.10 宽的角色圆心通道（可挤过但很窄，该角落无米点与门）。两项均**按现行值保留**（2026-09-25 用户决定：先浏览器实机走一遍，真别扭再微调；稳定 ID 优先于命名整齐）；理由、实测数字与未采纳的备选值见 `docs/S7C_HIDE_RANDOMIZATION_DESIGN.md` §3.4。
- **未授权**：S7C-1B（进入 / 退出 / 检查玩法）仍未授权；本节只有地图数据与调试标记。

## DEV｜场景热编辑器（仅开发模式）

- 开发模式下地图可在游戏内热编辑：右上角「场景编辑」打开后自动冻结双阵营，可选中家具 / 纸箱 / 藏身锚点，调整 X/Z、朝向（家具只支持 90° 整数倍）、白模尺寸与锚点 `facing`。
- 编辑**不改本文件、也不改 `apartmentMap.ts`**：数据分为「原始地图 / 内存草稿 / 已应用数据」三层，只有点「应用编辑」并通过校验后才会安全重建静态碰撞与导航网格；非法编辑（越出房间、堵门、压米点或出生点、切断连通性、锚点进墙或与家具脱离、家具重叠）会被拒绝并回滚到上一个合法状态。
- 导出 JSON（`format: who-ate-my-rice/apartment-map`）只含已应用数据，包含房间 / 门 / 出生点 / 米点参考与家具位置、旋转、尺寸、藏身锚点 `facing`，可作为未来 UE 导入公寓白模的稳定空间数据。设计与验收细节见 `docs/DEV_SCENE_EDITOR_DESIGN.md`。
