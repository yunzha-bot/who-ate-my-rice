## 1. 复现与判定

以现有工作区运行两项原测试，稳定得到0/2通过：

- `tests/difficulty.test.mjs`：NORMAL / 20276765持续追逐12000帧后仍为PLAYING，而非测试期待的FINISHED。
- `tests/throwables.test.mjs`：throw_closet_1距离rice_10约1.463，未满足测试硬编码的1.8。修正这一检查后，同一测试还暴露south_hall只有1件的旧断言。

没有把失败直接认定为AI锁死或地图错误。固定种子轨迹显示，AI仍在移动、避让和换房间，剩余米点有合法路径。对照试验保持原AI、锁门、地图、数值及12000帧预算不变，只让脚本Human在180秒后沿真实导航和碰撞离开争夺区域，NORMAL / 20276765在242900ms完成5/5。持续守点会阻止AI安全进食；游戏没有对局时限，不能把“持续追逐时十分钟内必须结束”作为锁门安全规则。

道具布局由现有 `validateThrowableLayout` 判定合法。当前编辑/保存契约要求：房间内0.3边距、可站立圆0.38及高度1、门中心距离至少门宽/2+0.4、米点/躲藏点间距至少0.45、物件间距至少0.55。旧1.8是初始分布的额外留白，不是当前编辑保存准入条件。用户还已将 `throw_south_hall_2` 移至east_hall：编辑器会更新roomId并保留稳定ID，因此“每个现房间永久恰好两件”也不是保存契约。

## 2. 实际修改

- `tests/difficulty.test.mjs`：固定场景先持续追逐180秒，再让脚本Human正常走到公开地图中的合法撤离格。仍使用同一导航、门碰撞和移动通道，没有传送、开锁、忽略碰撞或停用AI。保留原12000帧预算、每次新增锁后逐个剩余米点可达、确实发生合理锁门及最终FINISHED断言；新增DeepSeek获胜必须5/5且原因为RICE_COMPLETED的断言。
- `tests/throwables.test.mjs`：按实际编辑/保存契约检查当前布局。保留36件总数、唯一ID、每个原始区域的两枚稳定ID、类型、实际所在房间、碰撞和交互安全检查。允许用户合法跨区移动，不挪回用户道具。新增3项回归，分别覆盖门/锚点/米点/房间/家具碰撞边界、物件互相重叠边界，以及跨区时必须正确更新roomId且不能改稳定ID。

这不是让原连续追逐场景被迫获胜，也不是调整AI平衡或降低运行时保存阈值；修正了测试对无对局时限及已获准自由摆放行为的误判。原连续追逐对照仍可能长时间不结算，不能据本轮宣称所有玩家策略都限时结束。
