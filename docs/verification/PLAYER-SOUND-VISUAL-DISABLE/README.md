# 玩家声音探测可视化停用：浏览器复核记录

本轮为「停用玩家端声音范围圈 + 彩色动态声纹」的**真实浏览器**复核材料。
停用方式、归档与恢复步骤见 `archive/features/player-sound-visual/README.md`。

- 脚本：`browser-check.mjs`（本机 Chrome headless + CDP，可复现）
- 运行方式：`node browser-check.mjs <本目录> after`（停用后）与 `… before`（停用前）
- 开发服务器：`http://127.0.0.1:5173/`（复用本项目已在运行的 Vite dev server，未另起服务）
- 固定种子：URL `?matchSeed=20260927`（S7C-3 的复现入口）——**两轮出生点、门初态、镜头与角色站位一致**，
  因此像素差异只来自被停用的表现层
- 采样时机：进入「对局中」后立即采样；每段采样前都用真实的 Esc →「重新开始」拿一个新对局窗口
  （开发配置单局只有约 5～11 秒）

## 1. 复现「停用前」的方法（已还原）

停用后源码里 `PLAYER_SOUND_VISUAL_ENABLED` 为 `false`。为了做同一场景的前后对照，
「停用前」一轮是把该常量**临时**改成 `true` 后运行，运行结束**立即写回 `false`**：

- 改前/改后文件 SHA-256 一致：`92C63B64D53875809476B8E6D87514D3E0CD4FF62964803CC1194D206EC54468`
  （脚本输出 `hash matches original: True`）
- 两轮都先向开发服务器请求一次 `src/three/ThreeGame.ts`，把「服务器此刻在发哪一版」写进日志：
  - `after` 轮：`PLAYER_SOUND_VISUAL_ENABLED = false`
  - `before` 轮：`PLAYER_SOUND_VISUAL_ENABLED = true`
- 两轮 `soundVisual?.update` 调用点都还在（各 2 处，由常量守住），这正是「接线隔离而非删代码」的预期。

## 2. 范围圈：同一场景的前后对照（决定性证据）

度量：声音范围圈 / 阈值圈专属色 `0xb5d8e5` 的像素数（±14；该色只出现在 `SoundVisualView` 的四个面上）。
容差是实测选出来的：±6 会因为圈下方的地板颜色不同而漏计，±20 会把淡紫 / 淡蓝地板算进来。

| 采样点（均在「对局中」） | 停用前（常量 `true`） | 停用后（常量 `false`） |
|---|---:|---:|
| 静止首帧 `01-idle` | **13,515** | **359** |
| 静止 6 帧 `02-idle-burst` | **13,515 – 13,729** | **359 – 555** |
| 临时控制 Human 后首帧 `03-possess` | **13,499** | **359** |
| 声纹采样 6 帧 `04-possess-burst` | **13,512 – 13,534** | **359（恒定）** |
| 移动后首帧 `05-moved` | **36,448** | **564** |
| 移动 6 帧 `06-moved-burst` | **35,930 – 36,618** | **550 – 673** |

差值 25～60 倍，停用后剩下的几百像素是场景本身颜色（淡紫 / 淡蓝地板），不是圈。
截图对照（同一固定种子、同一站位）：

- `before-01-idle.png` / `after-01-idle.png`
- `before-03-possess.png` / `after-03-possess.png`：**停用前**能同时看到半径 18 的大圈与角色身上 2.5 半径的近圈；
  **停用后**两条都消失，而同一画面里的 DEV AI 安全路径粉线**照旧存在**——说明差异不是渲染或面板造成的。

## 3. 彩色声纹：本轮**没有**拿到决定性的前后对照（不得当作已实测）

- 停用后侧是确定的：`SoundVisualView` 根本不会被实例化，`waveGroup` 不存在，
  `after-*.png` 里也没有任何声纹弧线；生产打包产物中 `SoundVisualView` 的特征标识**全部为 0**
  （见 `docs/AGENT_LOG.md` 本轮的打包静态核对）。
- **停用前侧本轮未覆盖**：脚本在「临时控制 Human 并让 Human 走一段」这一步成功点到按钮
  （`临时控制 Human：CLICKED`、面板显示「当前控制对象：Human」），但该固定种子下 Human 距离
  观察者（DeepSeek 娘）太远，采样窗口内没有出现可听声音事件，没有一帧显示声纹。
- 颜色计数也不能当判据：声纹是半透明混合色，**任何「贴近纯色」的容差都测不到它**；
  日志里的「蓝色声纹像素」（辅助值）两轮区间重叠（停用前 3,114–4,798，停用后 2,128–3,861），
  它包含场景本来就有的蓝色元素，**不能用来判断声纹有无**。
- 因此「停用前有彩色声纹」这一侧目前只由源码与单元测试支持（`tests/sound-visual.test.mjs` 中断言
  `waveGroup.visible === true`、声纹按 NEAR/MID/FAR 换色、并在同心带内扩散），
  **本轮的浏览器实测没有覆盖它**。这一项请在人工验收时肉眼确认。
- **用户的集中人工验收（3/3 PASS，含「声音探测完全消失」）已单独覆盖该项**；该结论是用户人工确认，
  与本节的「代理浏览器覆盖缺口」是两条独立证据，分别记录、不互相改写（人工验收不写成代理实测，
  代理实测也不改写人工验收结论）。

## 4. 控制台与对局过程

- 两轮控制台异常都是**无**；只有既有的 `THREE.Clock` 弃用告警 1 条（非本轮引入）。
- 所有 burst 采样帧都落在「对局中」（6/6 或 7/8），没有把结算后的空画面当成证据。
- 脚本走过的真实交互：阵营菜单选 DeepSeek 娘 → 进入对局 → DEV `Details` 面板 →
  临时控制 Human / 归还控制 → Esc 暂停菜单 →「重新开始」→ WASD 移动。

## 6. 已知限制（不记为已通过）

- 声纹的停用前后对照缺一轮（见第 3 节）。
- 证据来自 Vite 开发服务器；正式构建侧只有「打包产物不再包含表现层代码」的静态核对，
  **没有**在生产构建里跑完整对局。
- 未覆盖：不同浏览器 / 无痕模式、极窄或超宽窗口。
- 「临时控制 Human」这一步依赖 DEV 面板按钮，若将来该按钮改名，脚本需要同步修改。
