## 使用方法

1. 使用开发入口 `http://127.0.0.1:5173/`，进入对局后打开“场景编辑”。正式预览4173不提供DEV编辑器，这是预期行为。
2. 在“可投掷道具 · 位置编辑”选择道具，或直接在场景中点击并拖动。可用“聚焦道具”定位，再改X/Z。拖动坐标保留三位小数，数值输入不额外量化。
3. 推荐统一点上方“应用编辑 → 保存布局”：同时处理已修改的家具、藏身点和道具。只想处理道具时也可点下方“应用道具位置 → 保存道具位置”。仅应用不会跨刷新保存。
4. 家具及藏身点仍写 `sceneLayout.json`，道具仍写 `throwableLayout.json`；统一保存入口不把两类数据混进一个文件。
   开发5173保存后会刷新读取新点位；生产4173读取上次构建快照，后续改完布局需重新 `npm run build` 才同步到正式预览，不是仅刷新4173就更新源码JSON。
5. “放弃道具草稿”及关闭编辑器会放弃尚未应用的道具编辑；已应用但未保存的位置保留于当前会话，并有未保存提示。离开页面会提醒未保存内容。

## 实现范围

- Human的 `AlphaPresentation.ts` 已与角色试作前文件逐字节相同，保留原方块造型和动作。本轮只撤销了上一未交付试作自行新建的 `HumanHomeModel.ts` 及专属测试；没有删除任何原始模型、旧资源或用户文件。
- `ThrowableEditor` 为现有场景编辑面板的小节，复用原 `SceneEditorView` 的拾取、拖动、聚焦和高亮，不创建第二套鼠标拖动系统。编辑期间展示36件初始物件的独立预览，不复活本局已消耗的物件；应用位置不移动手持或飞行物，新开局使用已应用初始布局。
- `ThrowableLayoutModel` 分离草稿、应用、项目保存状态；只能改位置，稳定ID与类型只读。跨房间移动会根据实际房间更新roomId。检查有限坐标、房间边距、真实旋转家具/墙体碰撞、门口、锚点/米点及道具间距；非法草稿不能应用或保存。不是新寻路规则，也不移动家具。
- 新接口 `/__dev/throwable-layout` 只在Vite开发服务器注册；带来源检查、大小限制、版本冲突拒绝、自动备份和临时文件原子替换，仅写投掷物JSON。保存失败保持未保存状态，不声称成功。没有开放生产保存接口。
- 轨迹用 `LineDashedMaterial` 与每次更新后的 `computeLineDistances()`，为米白色虚线；范围圈和落点标记保留，不恢复声音圈或声纹。
- 唯一玩法数值变化是用户批准的 `GAME_CONFIG.throwables.stunDurationMs: 2000 → 3000`；重复命中刷新到3秒而非累加。原冲刺摔倒时间不变。
