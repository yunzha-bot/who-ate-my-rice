# S7C-2 第四轮修复轮：白色家具轮廓可见性的浏览器证据（2026-09-26）

本轮**只修白色呼吸轮廓的可见性**（用户人工验收六项里只有第 3 项 FAIL，补充说明「玩法实际上都可以，唯一观察到的问题是没有白色轮廓呼吸」）。玩家 Q 的判定逻辑一字未改，`GAME_CONFIG` 零改动。

## 1. 根因

| # | 根因 | 证据 |
|---|---|---|
| ①（主因） | `src/three/HideSearchView.ts` 的表现层根节点 `root` 被 `show()`（**普通扇形释放**）搬到玩家释放点并带上朝向，而挂在它下面的玩家白色高亮 / AI 扇形 / AI 轮廓 / 命中反馈传进去的都是**世界坐标** → 被**二次平移**。 | 真实 `three` + 真实 `HideSearchView` 的 Node 探针（`node --experimental-strip-types`）：在 (-11.4,-5) 按过一次 Q 之后，`hide_main_bed` 中心 (-13,10) 的高亮世界坐标变成 **(-25.43, 0.23, -13.49)**（期望 (-13, 0.225, 10)），偏差约 28 世界单位——已经在公寓之外。 |
| ②（次因） | 旧实现是 `BoxGeometry` + `wireframe` 的**三角形线框盒**（面内还有对角线），且 `scale.y = height` 让顶面与家具顶面**完全共面**产生深度冲突；1 px 线条在浅灰地面附近对比也不足。 | 修复前真机上从未出现过「呼吸峰值接近纯白」的像素；修复后同一位置有 116–176 个（床）/ 88 个（纸箱）。 |

**用户看到的现象**：DEV 行显示「高亮 FURNITURE（hide_main_bed｜合法 是｜指向 是 45.0°）」、HUD 显示「Q：可用」，但屏幕上没有任何白色轮廓。

## 2. 修复（`src/three/HideSearchView.ts`，纯表现层）

1. 根节点**恒为单位变换**；扇形自己携带 `position` 与 `Ry(朝向) · Rx(−90°)` 四元数——世界矩阵与旧实现逐值相同（矩阵对比最大误差 `2.2e-16`，测试对 3×3 旋转元素逐一断言）。
2. 白色高亮改为**真实家具棱线轮廓**：`EdgesGeometry(单位立方体)` 的 12 条棱（24 顶点）+ `LineBasicMaterial`，与家具网格**同中心 / 同朝向**、三轴各外扩 `HIDE_PLAYER_TARGET_MARGIN = 0.08` 贴合外缘；不涂白家具本体、不遮挡家具材质。
3. 呼吸透明度区间 **0.25–0.8 → 0.35–1.0**（周期仍 1,400 ms；冷却期仍压到 0.14）。
4. 几何与材质只创建一次并长期复用，每帧只改 `scale / position / rotation / opacity`。

## 3. 脚本与用法

```powershell
# 需要先有一个 dev server（本项目固定 http://127.0.0.1:5173/）
node --experimental-strip-types browser-check.mjs <bed|carton> <outDir> <tag>
#   tag = after  ：当前（已修复）代码
#   tag = before ：把根节点位移缺陷临时改回去的对照组（仅用于取证，跑完必须还原）
```

脚本流程：真实按键走图 → 背对按一次 Q（旧缺陷正是在这一步搬走根节点）→ 等 12 秒冷却 → 面向家具 → **同一相机、同一站位**每 ≈250 ms 截一帧共 14 帧 → 在 Node 里解码 PNG（自带 PNG 解码 / 编码，用于放大留证），筛出「呼吸峰值接近纯白 + 明暗振幅 ≥40 + 中性」的轮廓像素并统计。DEV-B 只用**内存覆盖** `capture.radius = 0.05`、`movement.playerSpeed = 30`（避免脚本走图被抓、避免 AI 在测量期间吃满米结束对局），不改正式配置。

## 4. 结果（本轮实测）

| 场景 | 轮廓像素 | 屏幕区域 | 呼吸最暗 → 最亮（轮廓区平均亮度） | 冷却中 | 判定 |
|---|---|---|---|---|---|
| 主卧床（修复后） | 176 | 184×116 px | 185.9 → 245.4（振幅 59.5） | 163.9（明显更暗） | **PASS** |
| 储物间纸箱（修复后） | 88 | 81×50 px | 162.6 → 243.0（振幅 80.4） | 129.5（明显更暗） | **PASS** |
| 主卧床（**根节点位移缺陷改回去**的对照） | **0** | — | — | — | **FAIL** |

- 两个 PASS 场景里，每个采样相位的轮廓区平均亮度都 >155（底色约 116），即**每一帧都看得见**；按 Q 进入冷却后亮度掉到 163.9 / 129.5，与 HUD「冷却中 X 秒（家具描边变暗，暂时不能按）」一致。
- 对照组：DEV / HUD 全部显示「可用 + 已选中家具」，但 14 帧里轮廓像素为 **0**，屏幕上看不到任何白色轮廓。
- 留证文件：

  - `after-bed-breath-min/max.png`、`after-bed-cooldown.png`、`after-bed-baseline-backwards.png`（及 carton 同名文件）：整帧原图。
  - `after-{bed,carton}-summary.json`：全部 14 帧采样值、掩膜区域、判定指标。
  - `before-bed-no-outline-facing.png`：对照组「有提示、无轮廓」的整帧原图。
  - `after-{bed,carton}-log.txt`、`before-bed-log.txt`：脚本日志 + 浏览器控制台（只有既有 `THREE.Clock` 弃用告警与 favicon 404，0 页面异常）。

## 5. 本轮局限（不得写成 PASS）

- 「背对家具 → 无轮廓」**没有**做像素级对照：背对是靠**真实走位**转身，相机随之平移，整屏都会变化，同一相机的像素差无法成立。该状态以 DEV 读数（`高亮 NONE（合法 否｜指向 否）`）+ 真实地图自动化测试为证据（见设计文档 §4.7.2）。
- 「玩家指向家具 + 未藏身暴露目标同帧」仍然 **BLOCKED**（原因与 4 次尝试见 `docs/S7C_HIDE_RANDOMIZATION_DESIGN.md` §4.7.2），本轮未触及该分支。
- 本轮只改 Human **玩家** Q 的白色高亮；Human AI 的暖橙轮廓保持原颜色 / 透明度 / 触发时机，只随根节点修复回到正确位置。
- `before` 对照是把缺陷临时改回去跑的（`%TEMP%` 备份 + 跑完还原 + 文件哈希核对），**仓库里没有留下任何变异残留**。
