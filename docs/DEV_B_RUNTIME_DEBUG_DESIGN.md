## 1. 目标与边界

DEV-B 是**独立 DEV 工具**，接入现有 DEV Details 面板，不替换已验收的 DEV-A 场景编辑器。

- 只服务开发环境：入口按钮与面板沿用 `sceneEditorEnabled` 同级的开发环境判定（`import.meta.env.DEV` 且开发调试开关开启），生产构建不显示入口与数据。
- **不新增自动冻结状态**：需要暂停时继续使用既有 `MANUAL_DEV_FREEZE` / `SCENE_EDITOR` 冻结。
- **不修改正式游戏机制、不新增 AI 状态**，不实现藏身玩法、`CHECK_HIDE`、出生点随机化与 DEV-A JSON 导入器。

## 2. 三层职责分离（用户批准的总体架构）

| 层 | 职责 | 实现 |
|---|---|---|
| A. 只读运行状态采集 | 读取现有 AI / 感知 / 移动 / 抓捕的真实状态，**不改变其决策** | `src/systems/DevBObserver.ts`（纯函数） |
| B. 运行时参数覆盖 | 由统一内存覆盖层提供**有效配置值**；`GAME_CONFIG` 始终是只读基准 | `src/systems/RuntimeDebugOverrides.ts` + `src/systems/DevBRuntimeBinding.ts` |
| C. Three.js 调试可视化 | 用真实状态与真实判定结果绘制圆 / 线 / 路径 / 标记，**不另建一套模拟判定** | `src/three/DevBView.ts` |

**禁止假调节**：面板数字、运行时系统与场景可视化共用同一份有效参数。所有可调字段都由真实系统通过覆盖层的 typed getter 读取（`captureRadius` / `visionRange` / `playerSpeedPx` / `humanSpeedMultiplier` / `humanAIMovementMultiplier` / `soundRange()` / `soundStrength()` / `soundLifetimeMs()` / `distanceFalloffPower` / 四个声音削弱系数 / `minimumAudibleStrength`），没有"只改 UI 显示"的字段。

系统侧接入点（真实读取路径）：

- `PerceptionGeometry`（可选第 4 参 `OcclusionTuning`）：声音遮挡系数。
- `SoundEventSystem`（可选构造参数 `SoundTuning`）：`emit` 用有效强度/寿命（**只影响新事件**），`analyzeBy` / `heardBy` 用有效范围、衰减指数与最小可听强度。
- `VisionSystem`（可选构造参数 `VisionTuning`）：`update` 用有效 `visionRange`。
- `HumanAIController` / `DeepSeekAIController`：`setRuntimeTuning()`；Human AI 的路程时间估算、DeepSeek 的安全通过半径（`passageAvoidRadius`）、记忆路线可见性与掩护判断都读有效值。`DeepSeekAIController.currentPath()` / `HumanAIController.currentPath()` 是只读的缓存路线访问器（不触发新寻路）。
- `CaptureZoneView.setRadius()`：抓捕圈视图与真实抓捕判定同半径。
- `AISafetyPathView`：安全路径可视化按有效抓捕半径绘制。
- `ThreeGame`：抓捕资格判定、玩家与 Human 移动速度、观察数据采集、`resetRound()` 清覆盖、`dispose()` 释放 DEV-B 资源。

## 5. 生命周期与恢复

- 覆盖项**只存在当前页面内存**：不写 `src/config/gameConfig.ts`、不写 `docs/GAME_BALANCE_CONFIG.md`、不写地图 JSON V3、不使用 `localStorage`。
- 打开 DEV-B 时记录一次"打开时快照"；面板提供 **① 恢复打开 DEV-B 时的参数** 与 **② 恢复正式默认值（清除全部覆盖）**。
- 隐藏 / 收起 DEV 面板或关闭 DEV-B 面板：**保留当前临时参数**，游戏继续使用（关闭 ≠ 恢复默认）。
- 重新打开 DEV-B：以当时有效值重新建立"打开时快照"。
- 新局 / 重开（`ThreeGame.resetRound()`）：清除全部覆盖，回到正式基准。
- 刷新网页：内存自然清除。
- `ThreeGame.dispose()`：释放面板 DOM、定时器、绘制对象与订阅，不留下失效引用。

## 8. 已知限制（面板中如实标注）

1. `PerceptionGeometry` 只把**墙体与门**当遮挡几何，**家具不参与视觉遮挡**；即使 DEV-A 已实现旋转家具碰撞，也不得把家具遮挡画成正式视觉功能。
2. 现有视觉规则只有距离 + 遮挡，**没有视锥角**：不提供也不显示 FOV 控件或扇形。
3. Human AI / DeepSeek AI 的**卡住计时（`stuckMs`）等内部计时没有对外暴露**，面板标注「面板暂时看不到」，不做推测。
4. Human 的藏身检查（`CHECK_HIDE`）仍是预留状态，DEV-B 不实现、不模拟。
5. 观察刷新约 5–10 Hz（实测实现为 120 ms 节流）；**真实 AI 更新频率不变**，观察不触发额外寻路或决策。
6. AI 的**「原因」类自由文本代码**（`navigationReason` / `transitionReason` / `decisionReason` / `selectionReason` / `noMovementReason` / `recoveryBlockReason` / `safeWaitReason` / `sprintDecision`）**保留英文原代码**，只在悬浮说明里给中文解释——这些字段没有导出成联合类型，逐值翻译有猜错风险，保留原代码反而能与 AI JSON 日志逐条对照。已导出联合类型的枚举（对局阶段、阵营、视线状态、冲刺状态/风险、两套 AI 状态、锁门决策、威胁来源/等级、声音类型）一律显示「中文（原代码）」。

## 11. 中文说明与紧凑模式（2026-09-26 易用性优化轮）

用户反馈「调试面板专业术语较多，普通使用者难以理解」，本轮只做**显示层**易用性优化，不重构观察、调参、可视化与运行时覆盖层。

- **文案集中在一处**：`src/systems/DevBHelpText.ts` 是全部新增中文的唯一来源——38 项参数说明（11 项手写 + 9 类声音 × 3 项模板生成）、4 个分组说明、5 个观察分区说明、60 个状态字段说明、状态码中文映射表。文案不参与任何判定，也不改 `GAME_CONFIG`。
- **保留内部标识**：字段名、ID、配置键、单位、状态码全部保留；悬浮说明里给出真实配置键（如 `GAME_CONFIG.match.captureRadius`）与内部字段路径（如 `humanAi.state`），便于与源码、AI JSON 日志对照。
- **三行说明的分工**：`它是什么`（这是什么值）→ `调大 / 调小`（改了会怎样）→ `何时生效`（由参数自己的 `immediate` 决定，不靠文案猜；只影响新声音事件的 27 项用琥珀色单独标出）。
- **空间控制**：参数说明只加两行短文本；**状态字段的解释放在悬浮说明里**（60 条状态行若各加一行会把面板撑长一倍），并在标签下加虚线 + `cursor: help` 提示可悬浮；分区与分组说明各一行。
- **紧凑模式**：`紧凑模式（隐藏说明）` 开关只切换面板根节点的 `data-compact`，由 CSS 收起说明（`.dev-b-param-what` / `.dev-b-param-adjust` / 分组与分区说明 / 顶部提示），**不新增、不删除任何 DOM**，因此反复切换不会让节点数或监听器增长。实测：说明模式面板文档高 6 978 px、紧凑模式 4 904 px，节点数均为 507。
- **通俗化无数据状态**：`不适用 / 当前无目标 / 暂不可观测 / 无` 全部改写为具体中文（`当前没有追逐目标`、`当前没有听到任何声音`、`面板暂时看不到（控制器内部计时 stuckMs，未对外暴露）`、`还没有看到过对方` 等），有测试禁止再出现裸哨兵值。
- **范围边界**：不改玩法规则、不改正式游戏机制、不新增 AI 状态、不改 `GAME_CONFIG`、不改任何控件与可视化开关的行为；`DevBObserver` 只改显示字符串，观察仍是纯只读函数。
