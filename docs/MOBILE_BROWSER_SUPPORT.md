## 输入生命周期

- 每根手指独立持有摇杆或按钮；其他手指的移动/抬起/取消不会抢占投掷或布网手势。摇杆有中心死区，方向归一化，保持原移动速度。
- pointerup 执行正常松手；pointercancel、失去捕获、取消按钮仅取消，不投出道具。布网在触摸期间预览，松手后仍由原系统确认合法性和布置耗时。
- 失焦、切后台、窗口尺寸变化、说明层、暂停、结算、重开及返回菜单会释放触屏持有状态。旋转到竖屏时，READY 保留剩余时间，PLAYING 进入原暂停；回到横屏后需主动继续。
- 原键鼠监听与按键边沿保留，触控命令没有自动派发 KeyboardEvent。
- 取消只作用于当前玩家的操作。DP 侧不显示 Human AI 布网状态，也不能通过自己的投掷取消入口中止对方布网；显示与执行分别设有阵营门禁。

## 显示与开销

- 手机优先横屏，竖屏显示旋转提示；未强制请求全屏或系统方向锁。使用 viewport-fit、动态视口高度及刘海安全区。
- 横屏菜单、操作说明、暂停、结算、解锁面板可滚动；手机技能按钮为独立触控布局。DEV 存在时，手机工具条避开原 DEV 入口。
- 粗指针设备渲染像素比上限 1.35、方向光阴影贴图 1024；桌面保留原上限 2 / 2048。仅降低绘制开销，未换模型、美术、音频、地图或玩法参数。
- 仍使用原完整 v6 就绪门禁与明确选择的简化模式；没有为手机自动绕过资源加载。
- DeepSeek 藏身时只保留一条状态提示“藏身中 · 按 E 离开”，不再叠加重复的长说明；退出提示为“已离开藏身，可以继续行动”。

## 验证口径

- Node 回归覆盖触控方向/按键边沿、多指所有权、取消不消耗道具、手机技能状态、布网预览/松手及旋转后的 READY/PLAYING。
- scripts/verify-mobile-controls.mjs 使用既有本地 Vite 和外部已安装 Playwright，在独立 Chrome/Edge 中测试手机视口。窗口内的 ThreeGame 实例及测试场景探针仅存在于拦截的本地测试页面，未写入生产入口。
- 受控场景会安排合法道具/门/家具/藏身/开关位置，并调用权威结算接口验证结算与重开；这不是自然整局、AI 平衡或真实手机帧率验收。
- 浏览器协议多点触控覆盖同时移动与瞄准；逐根抬手与取消的所有权另由回归测试覆盖。iPhone 尺寸的 Chromium 模拟不能代替 Safari/WebKit 或微信真机。
